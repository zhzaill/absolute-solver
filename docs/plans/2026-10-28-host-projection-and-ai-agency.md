# Host 投影与 AI 自主活动计划

日期：2026-10-28（Asia/Shanghai）  
状态：阶段一实现中；目录已实现，跨设备与 Coo 投影验收未完成
范围：Absolute Solver；Cortico/Coo 是复用对象，不在本仓库复制实现

## 背景与目标

2026-10-12 至 2026-10-27 是本项目走到当前阶段的过去 15 天，不是后续开发工期。接下来的工作按短阶段推进，每阶段单独验证，不预设固定总天数。

目标不是把 AI 限制在 Hub 设计的动作集合里，而是让 Cortico Persona 能发现并选择已接入的设备与服务。例如，操作者可以提前在靶机部署并启动 Host；Cortico 看到该 Host 与其可用的 Coo 服务后，自行决定让 Coo 去该设备上的新位置或执行已有动作。Hub 负责跨主机接入、路由和执行事实，不取代 Cortico 的工具决策。

## 原有职责与本计划的延续

| 部分 | 原有职责 | 本计划中的职责 |
|---|---|---|
| Cortico / Persona | 语义理解、响应/沉默/工具选择、既有 World 和工具体系 | 根据投递的环境事实自主选择目标 Host、服务和已有工具动作 |
| Hub | 连接、turn、设备发现、活动 Body、路由、Provider 编排、trace 与回执 | 维护可达 Host/Body 目录；按既定接入信任边界转发请求；记录访问和执行结果 |
| Host | 位于设备侧、持有本机服务与资源的运行端/桥接端；不是第二个 Persona 或权限决策中心 | 可预先部署在靶机并常驻连接 Hub，暴露本机已配置的服务与 Body 能力，执行被路由到本机的请求 |
| Body | 设备上的采集、播放、显示和动作执行及其本地事实 | 报告环境变化和真实执行状态；不持有共享 Persona、Hub turn 或全局运行权威 |
| Coo | Cortico 上的桌宠 World、形象包、renderer/body、动作词表及其工具 | 复用原运行时；不在 Solver 重画模型、复制动作词表或另造电脑操作工具 |

Host 不是所有客户端必须预登记的静态设备名单。普通 Body 可以动态连接 Hub；需要访问某台靶机的本机服务时，该设备必须有对应 Host/桥接进程在线。Host 在线和能力声明表示“可达/能做什么”，不等同于用户授权或动作已完成。

## 当前已知实现边界

- Solver 使用 WebSocket v1；Body `hello.caps` 是客户端自报能力，不能当成身份认证或权限授予。
- Hub 已有 Body 连接发现、active Body 路由、`render.cue`、`body.handoff` 和段播放回执；当前仍以单个 active output Body 路由表达与音频。
- `/host/connect` 提供短时 Host Panel 邀请；Host Presence 有 allowlist、短时 intent/grant/revoke，但仅是受限的 Presence 流程，不是通用 Host 服务发现或完整认证系统。
- Coo `/pet` 使用真实 renderer、figure/body 和 World 状态；本机服务当前绑定 loopback，Hub 或其他 LAN 客户端不能把自己的 `127.0.0.1` 当成 Coo 主机地址。
- Cortico CUA 已有自身的工具声明、屏幕观察与输入工具、用户确认策略和环境提示。本计划不复制这些策略到 Hub，也不为 AI 新增 Solver 专属动作沙箱。
- 仓库存在未提交改动。实施前必须保留并复核工作区改动，不得用本计划覆盖或清理既有工作。

## 阶段一：服务与 Host 投影

建立只读的 LAN 服务目录，使人和 Cortico 能看见实际存在的服务、设备与 Host。

- 目录条目表达服务名/类型、所属 Host、LAN 可达地址、运行状态、版本、能力、原生界面入口和状态更新时间；未知字段明确显示未知，不凭配置推断在线。
- 状态来自服务本身的健康接口或所属主机上的轻量 Host 投影端。Hub 不是所有服务的唯一探针，也不把 loopback 地址错误地发给远端客户端。
- Coo 的入口复用原 `/pet` renderer 和现有动作运行时；遇到 loopback、CSP 或 WebSocket 来源限制时，在 Coo 所在主机提供本机桥接，不改画鲸鱼、不复制 Coo 页面。
- 页面/目录只呈现服务状态和入口，不做模型决策、权限授予、工具执行、音频路由或执行事实替代。
- 默认只展示必要元数据，不公开密钥、token、完整对话、音频、屏幕内容或私人事件正文。

验收：第二台 LAN 设备可打开目录；Cortico、Coo、ASR、LLM、TTS 等实际部署服务可区分在线、离线、未知和仅本机可达；停止单项服务后其状态过期或变为离线；Coo 页面仍由原服务渲染；目录不可用不影响 Hub、Body、Cortico 本身。

## 阶段二：Host 接入与目标路由

把权限问题收敛为设备/Host 接入和本次网络可达性，不把每个表情、移动或工具步骤交给 Hub 审批。

- 操作者可在目标设备预先安装、配置并启动 Host；Host 常驻连接后向 Cortico/目录提供本机服务和 Body 能力事实。
- 接入信任回答“这台机器是否加入这个 Solver”；能力声明回答“它目前提供什么”；本次请求的授权回答“当前访问是否可通过”。这三者不得混为一谈。
- Hub 按既有部署信任与操作者设置核对来源、目标 Host、请求关联和有效接入状态，然后路由或拒绝网络访问；获准后由 Cortico 原有插件/工具执行。
- 复用已有身份与接入机制能满足需求时不增加第二套登录或权限系统；若现有机制不足，先在任务卡中明确缺口和最小兼容扩展。
- 离线、撤销、失联或地址变化时，状态如实反馈；不可把曾在线或旧 grant 当成当前可达。

验收：未接入 Host 不会被伪报为可用；预置 Host 上线后可被发现；Cortico 选择目标后 Hub 能把请求路由至正确 Host；无可达路径时返回事实性失败；Host 断开后不再发送新请求；路由与结果可用关联 ID 对账。

## 阶段三：环境变化、AI 决策与 Body 反馈

将设备环境和接入状态作为 Cortico 可理解的事实，保持决策所有权在 Persona。

```text
Body/Host 观察环境变化
  -> Host/Hub 将有界事实投递给 Cortico
  -> Cortico Persona 决定响应、沉默或调用已有工具
  -> Hub 核对目标接入/网络可达并路由
  -> Cortico 原有插件和 Coo renderer/body 执行
  -> Body/Host 回报实际结果
  -> Cortico 获得结果并决定后续
```

- Cortico 获得当前 Host、服务能力、在线/离线与本次访问状态摘要；状态变化可用结构化事件通知，重连后可重新读取快照，避免依赖未收到的单次事件。
- 环境变化、网页内容、设备回执仍是事实输入；不得伪装成用户控制指令或自行改写 Host 接入配置。
- Hub 的职责止于接入核验、寻址/路由、必要的访问放行和事实记录，不代替 Persona 判断“该不该跳舞”。
- Coo 动作继续由 Cortico 已有插件和 renderer 执行。Hub/Host 记录已接受、已送达、已执行或失败等事实；收到请求不等同于动作完成。
- 不在本阶段预设复制 Coo 的逐动作确认策略。Cortico 现有 tools、权限和用户设置继续生效；Solver 只在发现明确跨主机接入缺口时定义最小补充。

验收：一条可关联的真实链路证明 `Body/Host 环境变化 → Cortico 决策 → 目标 Host 路由 → Coo 原服务动作 → 执行回执`；Cortico 能区分 Host 在线、能力可用、访问拒绝和动作完成；重连后状态能恢复；Hub 没有生成第二个 Persona 决策；没有把 UI 展示、消息发送或模型工具调用误报成实际执行。

## 计划外事项

- 不把 Hub 改造成第二个 Cortico、通用工具执行器或新的动作沙箱。
- 不要求每个动作都重新取得 Hub 审批；不以大量主动警告替代清晰的 Host 接入配置。
- 不重写 Coo、Cortico World、Persona、Memory、动作 vocab 或电脑操作工具。
- 本计划不默认推进流式 TTS、gRPC、机器人运动或公开 SDK。
- 不以服务目录显示在线代替真实远程动作验收。

## 执行与证据

按阶段建立独立任务卡，每次只推进一个可验收主任务。任务卡需列出允许修改的仓库、服务端和 Host 侧范围，部署前置条件、测试、真实 LAN 验收、日志路径和回滚方式。每阶段报告写入 `D:\11\Logs\`，并在验收后更新 `docs/ABSOLUTE_SOLVER_CURRENT_STATE.md`、`docs/REQUIREMENTS_INDEX.md` 与相关协议/集成文档。不得因计划文字本身将任何能力标记为 `accepted`。
