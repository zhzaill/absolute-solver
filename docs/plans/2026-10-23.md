# 2026-10-23 Execution Plan

## Main Outcome

Deliver one visible end-to-end demo:

1. The server requests presence on an authorized desktop.
2. The desktop client either notifies or opens the full-screen Host Overlay according to its local policy.
3. The XuegerOS camera is processed by YOLO in memory.
4. Bounded visual observations appear in the Robotics World/monitor.
5. The robot remains under human motion control; Persona receives no `/cmd_vel` authority.

## Fixed Constraints

- Presence is not permission.
- A web page cannot bypass browser popup restrictions. True active arrival requires a local tray/desktop client.
- The first desktop client uses Tauri rather than Electron.
- Full-screen appearance requires an explicit `presence:show` grant, TTL, visible indicator, and immediate revoke.
- Raw camera frames never enter Persona context, trace, or disk.
- YOLO is semantic perception, not a collision-safety replacement for lidar.
- Autonomous motion stays disabled until the MCU watchdog and remaining `/cmd_vel` issues are resolved.

## 09:00-11:00 · Host Arrival Lease

Implement the smallest version of:

```text
presence.intent
  intent_id
  host_id
  reason
  urgency
  requested_scopes
  ttl_ms
```

Required behavior:

- Hub stores a short-lived, one-time intent.
- A local host policy returns `notify`, `appear`, or `reject`.
- `force` is not supported.
- Full-screen appearance requires `presence:show`.
- `presence:revoke` hides the overlay immediately.
- Every intent and decision emits a metadata-only trace event.

Acceptance:

- Unauthorized host receives no overlay.
- Authorized host can accept once and receive one overlay session.
- Expired or replayed intent is rejected.
- Revoke returns the desktop to its previous state.

## 11:00-14:00 · Tauri Tray Client MVP

Deliver a local tray application that can:

- stay hidden by default;
- show a system notification for ordinary arrival requests;
- show a full-screen Host Overlay only when policy allows;
- display a persistent “Absolute Solver present” indicator;
- expose a visible exit/revoke action;
- reconnect to Hub without duplicating presence.

The first release remains manually started. Always-on startup is a separate user decision.

Visual baseline:

- near-black background;
- restrained scanline and terminal treatment;
- one Absolute Solver sigil as the first-viewport signal;
- subtitle and voice state;
- no Live2D dependency in this milestone.

## 14:00-16:00 · In-Memory YOLO Camera Pipeline

Use the XuegerOS camera as the first visual Body.

Borrow proven components:

- YOLO model/runtime from a maintained implementation;
- ONNX Runtime or an existing YOLO runtime;
- start with a nano model at 320–640 input;
- CPU inference is the baseline because ASR, TTS, and LLM already occupy the server GPU.

Pipeline:

```text
MJPEG bytes
  -> bounded in-memory frame buffer
  -> YOLO worker reads only the newest frame
  -> structured detections
  -> bounded VisionObservation
  -> Robotics World / monitor
```

Rules:

- No JPEG or video file is written to disk.
- The buffer keeps only the latest frame plus a small timestamped history.
- Slow inference drops old frames instead of building a backlog.
- At most 20 detections per frame.
- Detections contain class, confidence, normalized bounding box, timestamp, and frame sequence.
- Raw images remain unavailable to Persona unless a separate `camera:capture` grant is active.
- A short-lived in-memory JPEG handle may be exposed to an authorized operator UI; it is never written to trace.

Initial acceptance:

- camera disconnect fails closed;
- no stale frame is reported as current;
- YOLO worker maintains at least 2 FPS or reports the measured limit honestly;
- no unbounded queue growth;
- monitor exposes frame age, dropped frames, inference latency, detection count, and camera state.

## 16:00-17:00 · Integration

- Map `xuegeros-car-01` to the read-only Body Adapter already implemented in XuegerOS.
- Add a read-only Robotics World projection for camera/YOLO, mapping, battery, and robot presence.
- Keep the existing Motion Gateway operator-only.
- Show visual observations in the Host Overlay and monitor without flooding Persona context.

## 17:00-18:00 · Test And Log

- Unit tests for presence intent, TTL, one-time use, revoke, and policy decisions.
- Unit tests for the latest-frame buffer and YOLO output bounding.
- Mock camera/YOLO smoke test with no disk writes.
- Optional live camera smoke only after the adapter is healthy.
- Update project daily log and `D:\11\Logs`.
- Commit and push the day’s verified changes.

## Must Not Regress

- Hub remains authoritative for turns, Body registration, active audio, permissions, and trace.
- One active audio Body remains the default.
- Presence cannot grant microphone, camera, screen, files, clipboard, or terminal access implicitly.
- Raw camera frames and YOLO tensors never enter long-term memory.
- Motion commands are never exposed to Persona in this milestone.

## Risks

- Tauri tray/autostart behavior may differ across Windows sessions.
- GPU headroom is insufficient; YOLO CPU latency may exceed expectations.
- Camera MJPEG availability is intermittent.
- YOLO can misclassify objects and must not be used as the only obstacle-safety input.
- Host overlay without a clear revoke path is a privacy failure, even if technically working.

## Definition Of Done

The milestone is complete only when an authorized Host receives one server-initiated presence request, the Overlay appears with a visible revoke control, the robot camera produces in-memory YOLO detections, and no raw frame or motion authority leaks into Persona or persistent trace.
